## Базовий випадок і рекурсивний крок

- `preorder(node)`: база — листок (порожній `children`) → лише його значення; крок —
  значення вузла, потім `yield from preorder(child)` для кожної дитини.
- `find_path(node, target)`: база — `node.value == target` → `(value,)`; крок — перша дитина,
  у піддереві якої знайдено ціль, з доданим значенням поточного вузла на початку шляху; інакше `None`.
- `height(node)`: база — листок → 1; крок — `1 + max(height(child))`. Для дерева, у якому
  те саме піддерево є дитиною кілька разів (`shared_tree`), наївна версія обходить
  `2**depth` вузлів, а з `@lru_cache` — лише `depth + 1` (кожен фізичний вузол раз).
- `fib(n)`: база `n < 2`; крок `fib(n-1) + fib(n-2)`.

## Ліміт рекурсії CPython і відсутність TCO

`sys.getrecursionlimit()` за замовчуванням 1000 кадрів; глибша рекурсія дає `RecursionError`.
CPython свідомо не робить tail-call optimization: навіть «хвостовий» виклик
`return f(n - 1, acc)` створює новий кадр стеку. Тому `preorder`/`height` на лінійному
дереві з кількох тисяч вузлів впадуть (це перевіряє тест `test_iterative_safe_on_deep_tree`),
а `dfs_iter`, `bfs_iter` та `height_iter` з власним стеком/чергою працюють для дерев
будь-якої глибини. Підняття ліміту через `sys.setrecursionlimit` ризиковане (можливий крах
інтерпретатора), тому для глибоких даних правильна відповідь — ітерація.
